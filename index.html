Compress an image to an exact file size in the browser: binary search on quality

Upload forms love limits: "up to 200 KB", "up to 1 MB". Users then search for a way to shrink a photo to a number, not to "some quality". Here is how I implemented that in a client-side compressor, and the edge cases that matter.

There is no formula from quality to bytes

The output size of a JPEG or WebP at a given quality depends on the content: noise and fine detail cost far more than gradients. Two photos at quality 80 can differ several times in size, so you have to probe.

The search

  1. Try quality 100 first. If the file is already under the target, return it untouched. Do not degrade an image that does not need it.
  2. Otherwise run a binary search over quality. About 7 probes narrow the range to roughly one quality point.
  3. Return the best fit: the highest quality whose output still fits, not the first one that fits.
let lo = 1, hi = 100, best = null
for (let i = 0; i < 7; i++) {
  const q = Math.round((lo + hi) / 2)
  const blob = await encode(img, q)
  if (blob.size <= target) { best = { q, blob }; lo = q + 1 } else { hi = q - 1 }
}

When the target is unreachable

For some images even quality 1 stays above the limit. Returning that file silently is a lie to a user who came for the limit. Return the smallest result, flag reachedTarget = false, and tell the user to reduce the resolution as well.

What I measured

A 5.61 MB PNG made of random noise (the worst case, since noise does not compress): target 1 MB gave 1.83 MB at quality 5 with the warning; target 5 MB took the fast path and gave 1.87 MB at quality 100. Random noise barely changes size between qualities, so treat this as a test of the edge cases, not of compression ratios on real photos.
